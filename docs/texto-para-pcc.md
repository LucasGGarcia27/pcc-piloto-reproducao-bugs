# Estudo Piloto de Viabilidade

Antes do experimento principal, foi realizado um estudo piloto de viabilidade técnica com um bug funcional documentado da implementação React do TodoMVC, uma aplicação SPA de código aberto de finalidade demonstrativa. Inicialmente, foi investigada a possibilidade de utilizar o Metabase e os casos mencionados no estudo ReBug. Entretanto, considerando as condições locais de infraestrutura e a necessidade de identificar uma versão defeituosa rastreável, foi selecionada a issue #2309 do TodoMVC, utilizando o commit ff43b02e59dfa604386bb382034b2cd07c2bcd8a. Nesse caso, o cancelamento da edição de uma tarefa não descartava a alteração, que era aplicada quando o campo perdia o foco.

Para isso, a versão original da aplicação foi executada localmente em um navegador Chromium, sem alterações em seu código. A reprodução de referência confirmou o defeito por meio da observação da interface, de registros estruturados e de capturas de tela. Durante essa execução, foram coletadas as interações do usuário, as requisições HTTP e os eventos de execução observáveis. Os dados foram separados e utilizados para gerar automaticamente os oito conjuntos de informação previstos na metodologia, mantendo o mesmo relato básico do bug. Após uma rodada preliminar de verificação da infraestrutura, foram removidas dos pacotes notas explicativas do pesquisador, preservando-se apenas os registros das categorias autorizadas.

Na sequência, foi realizada uma tentativa independente para cada configuração, utilizando o modelo gpt-6-astra por meio do Codex CLI, integrado ao Playwright. O modelo escolheu as ações a partir do relato e da interface observada, enquanto o executor restringiu as operações permitidas e restaurou o estado inicial entre as tentativas. A avaliação foi realizada separadamente, verificando a permanência da edição após o cancelamento e a aplicação posterior do texto alterado. Na rodada final, o comportamento defeituoso foi confirmado em 6 das oito configurações. Nas 2 tentativas restantes, foi observado o cancelamento defeituoso, mas não foi verificada a perda de foco exigida pelo critério completo definido previamente. Foram preservados os registros das decisões, das ações, do consumo de tokens e dos resultados.

Desse modo, o piloto demonstrou a execução do procedimento de reprodução, a geração dos pacotes, a separação das sessões e a verificação objetiva das tentativas. Contudo, a aplicação selecionada não utiliza uma API funcional para as tarefas, e não foram observados erros JavaScript relacionados ao defeito. Assim, os dados de comunicação e de eventos de execução tiveram conteúdo diagnóstico limitado. Além disso, o caso envolve um fluxo curto e uma única tentativa por configuração, não permitindo inferências estatísticas nem conclusões sobre a contribuição das categorias. Portanto, a viabilidade foi demonstrada para a infraestrutura empregada, permanecendo necessária a seleção de bugs com informações das três categorias mais relevantes e a realização de repetições independentes no TCC.
